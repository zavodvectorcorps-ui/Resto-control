# RestoControl — Локальный агент печати

Мост между облачным бэкендом RestoControl и чековыми принтерами в вашей локальной сети.
Работает по схеме из техспеки: бэкенд рендерит ESC/POS, агент — «тупой релей» (base64 → raw TCP :9100).

## Почему нужен агент (а не печать напрямую из облака)

Принтеры стоят в вашей локальной сети за роутером и недоступны из интернета.
Агент запускается на устройстве **в той же сети, что и принтеры**, и сам ходит наружу
к бэкенду (polling) — поэтому проброс портов на роутере НЕ требуется.

## Требования

- Node.js 18+ (или Docker)
- Устройство в одной сети с принтерами (ноутбук / мини-ПК / Android TV Box)
- Статические локальные IP за принтерами (DHCP reservation по MAC на роутере)

## Быстрый старт (Node.js)

```bash
cd print-agent
cp .env.example .env
# отредактируйте .env: BACKEND_URL и AGENT_API_KEY
# AGENT_API_KEY возьмите в админке: раздел «Печать» → «Агенты» → скопировать ключ
node agent.js
```

## Запуск в Docker

```bash
docker build -t resto-agent .
docker run -d --restart=always --network host \
  -e BACKEND_URL="https://ВАШ-АДРЕС" \
  -e AGENT_API_KEY="КЛЮЧ_ИЗ_АДМИНКИ" \
  resto-agent
```
`--network host` нужен, чтобы контейнер видел принтеры в локальной сети.

## Настройка принтеров

В админке (раздел «Печать») для каждого принтера укажите:
- **Станция**: `kitchen` (кухня), `bar` (бар) или `precheck` (пречек-касса)
- **Цех**: к какому цеху привязан принтер (для kitchen/bar) — по нему идёт роутинг заказов
- **local_ip / port**: адрес принтера в сети (порт обычно 9100)
- **codepage**: `CP866` или `CP1251` — зависит от модели принтера

### ⚠️ Кириллица
Большинство ESC/POS-принтеров не понимают UTF-8. Бэкенд выставляет кодовую страницу
командой `ESC t n` (CP866 → n=17, CP1251 → n=73). Если на первом тесте вместо текста
«кракозябры» — поменяйте codepage принтера в админке на другой вариант.
Точную codepage нужно проверить по факту на каждой модели принтера.

## Как это работает

1. Официант отправляет заказ → бэкенд группирует **новые** позиции по цеху → создаёт
   `print_job` (ticket) на нужную станцию, рендерит ESC/POS в `payload` (base64).
2. Гость просит счёт → `print_job` (precheck) на станцию precheck (с ценами и итогом).
3. Отмена уже напечатанной позиции → `print_job` (void) — «СТОРНО» на ту же станцию.
4. Агент раз в ~1.5с забирает pending-задания, печатает, отчитывается printed/failed.
5. При сбое — ретраи 5с/15с/30с, затем `failed` (виден в админке).
6. Раз в 30с — heartbeat + пинг принтеров (в админке видно online/offline).

## Демонстрация без железа

Если принтеров пока нет, в админке («Печать» → «Очередь заданий») есть кнопка
**«Запустить эмулятор»** — она проигрывает поток печати в облаке и показывает
содержимое чеков, как они уйдут на принтер.
